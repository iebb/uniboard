# Font comparison API (UI integration contract)

App-only types in `App/FontComparisonEngine.swift`; shared records remain exclusively in FontLibraryContracts.

- `FontInspection(originalText: String, characterName: String, presentation: FontPresentation = .original, scaffold: FontScaffold = .automatic)`; enums presentation `.original/.text/.emoji`, scaffold `.automatic/.none/.dottedCircle`. `previewText` preserves exact supplied bytes in `.original`. `canChoosePresentation` is true only for a single emoji-capable base scalar optionally followed by VS15/16. On those inputs an explicit `.text/.emoji` choice replaces/adds the final selector without changing `originalText`. For all other sequences hide/disable the chooser: no arbitrary ZWJ or multi-scalar surgery occurs. `originalText` alone is copied. `isApplicable` excludes invisible-only controls. `usesDottedCircle` exposes the explanatory state.
- `FontComparing: Sendable`: `inventorySnapshot() async throws -> FontLibrarySnapshot`, `scan(_ inspection: FontInspection) async -> AsyncThrowingStream<FontScanUpdate, Error>`, `invalidate() async`.
- `FontComparisonEngine()` is an actor. `FontComparisonEngine.shared` is available. Each scan supersedes earlier scans. Cancel the consuming task on navigation; call `await engine.invalidate()` after download/remove, then rescan. No UI observer or global font selection is installed.
- `FontScanUpdate`: `generation: UInt64`, `checked: Int`, `total: Int`, `verified: [FontFaceRecord]`, `unknownCount: Int`, `isComplete: Bool`. Verified is cumulative, stable sorted. Unsupported count is checked minus verified minus unknown. Invisible inspection yields unknown (not verified) for each face; UI must use `isApplicable` for its not-applicable explanation. Generation is scan identity, distinct from library snapshot generation. Never label unknown faces unsupported.
- `VerifiedFontPreview(face: FontFaceRecord, inspection: FontInspection, pointSize: CGFloat)` is a SwiftUI UIViewRepresentable. A main-actor UIView creates, verifies, retains and draws the SAME CTLine. No CoreText reference travels from scanning actor to main actor. If revalidation fails it displays Preview unavailable, never fallback as a named-face match.
- `FontInventoryProviding: Sendable` has `snapshot() async throws -> FontLibrarySnapshot`, `fileURL(for: FontFaceRecord) -> URL?`, and `revisionFingerprint() throws -> String?` (default nil disables inventory caching). Injectable `PublicFontInventory(store: CustomFontStore = .shared)` supports persisted-library integration tests. Injectable engine initializer `init(provider: any FontInventoryProviding, cacheLimit: Int = 512)` supports fixtures. `cachedResultCount` and `cacheHitCount` are actor-isolated test diagnostics.

Inventory uses all public CoreText collection descriptors, physical bundled Fonts files, installed curated pack files, and the throwing `CustomFontStore.readLibraryState().snapshot` (same membership as localLibrary). A new install with no manifests is empty; corrupt manifests or unavailable shared storage fail the scan instead of silently hiding downloaded/imported faces. There is no 16-face enumeration cap. Unknown process provenance is Available, not System. Files use SHA256 + collection face index + canonical variations as INTERNAL physical dedup keys; process-only keys use actual PostScript name + canonical variations. These keys are not navigation IDs: local FontFaceRecord.id is preserved exactly (including `google:fileID:styleID`), so inventory, scan results and detail's persisted exact-ID lookup agree. For physical aliases, stable preference is Google downloaded record, other downloaded, imported, installed, included, system, available, then lexical persisted ID; this retains receipt/provenance and assetID. Decimal CoreText NSNumber axis identifiers and OpenType fourCC tags such as `wght` canonicalize to the same numeric axis for identity AND actual loading. Conflicting duplicate spellings are rejected as unknown. Physical URL evidence merges registered file aliases with local file identities. No bulk font registration occurs. File descriptors are metadata enumeration; actual CTFonts are loaded one at a time. The engine caches the complete immutable metadata inventory against the throwing local-library generation plus curated-pack revision; explicit `invalidate()` also clears this cache and must be called after process-font registration changes. It does not hash bundled binaries again for each inspection. Hashing is chunked with cancellation/yield points, and metadata loops yield between files/descriptors. New scans and invalidation cancel the prior worker task, including inventory work.

Proof intentionally conservative: single-face files are loaded directly as CGFont, not resolved by name. Actual collection file locators stay in inventory but are unknown: this implementation cannot prove selected physical collection face index via the public descriptor path. Single physical sfnt files are identified by their binary header, not descriptor count: a variable TTF may expose many named-instance descriptors, all at physical face index 0. Direct CGFont creation uses an axes-only descriptor so a different named-instance descriptor cannot redirect the requested font. Requested variation keys/values must be valid, and every requested coordinate must match effective coordinates within 0.0001. CoreText reports only nondefault overrides in `CTFontCopyVariation`; effective values are declared `CTFontCopyVariationAxes` defaults overlaid with those overrides. Unknown axes remain missing, and silently ignored/clamped nondefault requests are unknown. Run font identity and nonzero glyph checks reject fallback and .notdef. Single scalars, supplementary scalars and simple Latin/Greek/Cyrillic text may verify. Combining scaffold is excluded from attribution; marks still require their own named-face glyph. ZWJ, variation-selector, base-plus-combining-mark, emoji modifier/tag/flag/keycap sequences, Indic and other complex multi-scalar script sequences remain unknown even when same-font shaping succeeds: same-font runs alone are not proof of correct contextual shaping. VS15 and VS16 are distinct exact-byte cache inputs. This release does not claim semantic correctness for complex shaping or keyboard availability; availability is app-only. Cache keys use Data UTF8, face identity, presentation/scaffold and inventory generation, never Swift String canonical-equivalence hashing. Cache is bounded and protects not-yet-consumed hits during sequential scans larger than its capacity, avoiding FIFO rescan thrash; CTFonts/CTLines are not cached across scans. Each preview view retains its own verified line and skips reshaping when its exact-byte configuration and library revisions are unchanged. Drawing unions typographic, glyph-path and image bounds and scales that same line to the actual available view bounds, preserving overhang and long specimens without substituting a different font.
