# Font library API (frozen integration contract)

Shared value types are in `Shared/FontLibraryContracts.swift` (internal module visibility, Codable/Sendable; no Core Text references).

- `CustomFontStore.shared.localLibrary: FontLibrarySnapshot` is synchronous, read-only and includes imported, installed and downloaded faces only. Merge process/included/pack inventory in the comparison engine. `generation` changes atomically with committed membership. `customEntryCount` counts binary/installed entries, not variable styles.
- `CustomFontStore.shared.url(forRelativePath: String) -> URL?` resolves immutable snapshot file locators safely, including paths from older snapshots after removal. Never register all fonts; open lazily with CGFont/Core Text. File locators use faceIndex 0 (single-face TTF/OTF), variable instance axes are in `variations`.
- Legacy `fonts`, `revision`, `url(forFilename:)`, `add`, `addInstalled`, `remove` remain. Old JSON is read without destructive migration. New writes use a single atomic manifest; legacy binary names remain resolvable.
- `CustomFontStore.shared.receipt(fileID: String) -> FontLibraryReceipt?` returns full offline licenses/provenance.
- App-only `@MainActor GoogleFontDownloadCoordinator(catalog: GoogleFontCatalogSnapshot, store: CustomFontStore = .shared, transport: any GoogleFontTransport = PinnedGoogleFontTransport())` publishes `states: [String: GoogleFontDownloadState]`, keyed by FILE id. Methods `download(styleID:)`, `cancel(fileID:)`, `remove(fileID:)` are `async throws`. All variable styles sharing a file download/remove together. Downloaded is saved/validated, not system-installed or character support.
- Typed failures/states are declared in the contracts. Cancellation throws CancellationError and sets cancelled; cancel after committed success never deletes a valid download.

Storage commits immutable binary + receipt/full licenses before manifest publication. Removal excludes membership first; immutable retired files are retained to keep cross-process snapshots usable (no immediate disk reclamation). A process-wide writer lock serializes legacy and Google mutations. Reader has no networking. Coordinator handles at most two transfers, pinned HTTPS GitHub raw URLs, rejects redirects, disables credentials/cookies, validates bounded streamed content and verifies hash/font/PostScript identity before commit. UI must refresh its inventory after operations; legacy UnicodeFontSupport checks revision and invalidates its lazy caches.

## Verification and deliberate boundaries

`FontLibraryStorageTests` covers safe paths/symlinks, legacy migration, quota 16/17, concurrent writers, invalid hash/magic/identity/size, cancellation at publication, valid binary commit, variable file deduplication, relaunch/licenses, snapshot-safe removal, corrupt manifest and redirect rejection. Valid font bytes are reconstructed from public Core Text tables in the test runtime (not a network fixture). `GoogleFontDownloadCoordinatorTests` uses injected transport for cancellation, shared variable-file state, retry and offline failures. These tests require the native app test target and have not been executed in the Linux editing environment; the parent owns native builds/membership.

No process-wide registration is performed: validation opens CGFont/CTFont directly and the lazy reader follows the existing implementation. The `registration` error means direct CTFont identity failure; downloaded does not certify keyboard or character coverage. Named variable instance PostScript names come from pinned catalog metadata; the binary's base PostScript name is verified against `expectedPostScriptNames`.

The 40 MiB transfer is incrementally received and hashed, then retained in bounded memory for native validation; it is not a streaming-to-disk transport. Transfer concurrency is limited to two. Writer serialization assumes the containing app is the sole writer; the keyboard is a read-only consumer. Retired binaries intentionally have no garbage collector yet. The manifest's atomic rename is the visibility boundary, not a multi-process writer lock or power-loss fsync protocol. Tests do not yet measure real-network redirect behavior, peak memory, device keyboard availability, or power-loss recovery.

## Review hardening / failure-aware reads

- `try CustomFontStore.readLibraryState() -> FontLibraryReadState` returns `snapshot`, `receipts: [String: FontLibraryReceipt]`, and `assetIDs: [String: String]` from **one** bounded decode/validation. Coordinator initialization uses this once, not one manifest read per catalog file. Callers needing explicit storage errors should use this throwing API, not infer an empty library from the compatibility `localLibrary` accessor.
- `CustomFontStore.libraryFailure: FontLibraryFailure?` exposes read errors; coordinator publishes `libraryFailure` for initialization/reconciliation failures. UI should show the existing storage-error presentation and retain navigation rather than claim the library is empty. `readLibraryState` maps malformed JSON and inconsistent metadata to `.storageFailure`; unavailable app-group root is `.storageUnavailable`.
- Both legacy and v2 reads now fail closed. Legacy malformed records are no longer silently filtered. Validation checks unique entries/file IDs/face IDs, binary hash/name consistency, ranges, installed-vs-file identity, membership, receipts, license hashes, locators, axes, and shared import ownership. Reads allocate at most the format cap plus one byte (4 MiB legacy; 8 MiB v2), and publication also enforces the v2 cap.
- Importing an already downloaded hash atomically records import ownership on every receipt referencing that binary. Removing Google receipts preserves imports in either ordering. A validated import/download repairs missing bytes; divergent existing immutable bytes fail explicitly rather than being silently overwritten. Repeating a download transaction no longer trusts an existing receipt without checking bytes.
- The coordinator initializer remains nonthrowing but validates the complete `GoogleFontCatalog` schema and trusted repository commit. An invalid catalog records failed states and cannot start transport or removal. Downloads use `GoogleFontCatalog.downloadURL(for:)`, not a caller-supplied arbitrary 40-hex pin. Before the downloaded fast path, the coordinator re-reads current receipt membership, so legacy removal followed by Download performs a new transaction.

New regression tests cover both import/download orderings, missing-byte repair and corrupt-byte refusal, duplicate/unsafe manifest metadata, malformed legacy preservation, cap-plus-one reads, untrusted commit with zero transport calls, and coordinator redownload after legacy removal. These remain unexecuted locally; no build was launched during review fixes.

### Manifest read cache

Repeated `revision`, `fonts`, `receipt` and snapshot reads share a validated manifest cache per store instance. Cache access is under the same recursive process-wide writer lock. Every access performs filesystem identity checks, not a JSON decode: selected format path, device/inode, size and nanosecond modification/change times. Atomic replacement is detected even with identical size/restored modification date. A bounded read is accepted only when the selected v2-or-legacy identity is unchanged before and after reading (three attempts maximum under external replacement). Missing files, migration to v2, corrupt replacements and permission/metadata errors invalidate the cache; errors never return previously cached data. Local commits clear their cache, while other instances/processes discover replacement through identity checks. Filename validation accepts legacy 16-digit SHA prefixes and new complete 64-digit hashes only, matching their persisted digest.

Regression coverage includes repeated cached reads, a second store's legacy-to-v2 migration and mutation, same-size corrupt atomic replacement with restored mtime, recovery, v2 deletion/legacy fallback, and complete absence. Tests remain native/unexecuted here; no builds launched for this change.

### Trusted container path boundary

`CustomFontStore(directory:)` takes the private library leaf beneath an OS-provided trusted container. Initialization canonicalizes the **parent container only**, accommodating `/var`/`/private/var` and other trusted-container aliases, then appends the original library leaf without resolving it. Library-root and descendant symlinks remain forbidden; component-based canonical comparisons ignore directory URL hints but not changed filesystem destinations. Tests cover a trusted-container alias, a substituted library-root symlink, nested symlinks, absent/existing directory-hint roots, and actual `/var` temporary-container alias when present (explicit skip on runtimes without that alias).

Native follow-up: whole-path Foundation symlink resolution is not sufficient when the terminal file is absent. Safe path resolution now additionally uses `lstat` on the library root and every descendant component, rejecting symlinks (including dangling links), non-directory intermediate components, special terminal nodes, and all stat errors except legitimate `ENOENT`. Manifest publication runs this guard before directory creation. Regression paths include symlink-to-existing-parent plus missing terminal, deeper missing terminal, dangling link, regular-file intermediate, and an ordinary new directory/file path. This is fail-closed path validation under the trusted-container/sole-writer model, not a claim of race-proof openat-style protection against a hostile concurrent filesystem writer.
